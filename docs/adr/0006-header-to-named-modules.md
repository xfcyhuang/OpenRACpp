# 自有代码全量迁移 C++ 命名模块（目录级聚合，一次性切换）

自有 86 头（.hpp+#include 拓扑）一次性迁移为 **21 个目录级聚合命名模块**（`.cppm` 接口单元只放 export 声明 + `.cpp` 实现单元），动机：touch `world.hpp` 触发 112/330 步重编（34%）、touch `miniyaml.hpp` 221/330（67%）——底层头改动即大半仓重复文本解析；BMI 替代后接口改动脉冲仍传播但每步成本从文本解析降为 BMI 加载。粒度按目录机械推导（`ora.<assembly>.<area>`），**include 互引簇并环不解环**：头级 DAG 本无环，但接口级前向声明附着规则（一实体只附着一模块）逼出 world↔network↔replay 接口互引簇，按票内裁定并入单一 `ora.game.world`（16 头）而非解耦重构，行为零变。BMI 各 build 树（base/asan/hardened）独立生成（CMake FILE_SET cxx_modules 天然按树隔离，std.pcm 旗级失配教训固化）。第三方边界豁免保留 `#include`：SDL2/windows.h/stb_truetype.h 于 TU 全局段或边界 TU（launcher main.cpp/探针）内照常引入，`ora.game.render` 接口单元全局段 include vendored stb_truetype.h（接口嵌 stbtt_fontinfo 成员，`FontFace` 布局随 BMI 序列化）；tests/test_util 无宏亦模块化（`ora.test.util`），自有 `.hpp` 白名单为空（src/*.hpp 清零）。否决：①逐目录渐进迁移（新旧风格长期并存，include 拓扑与新 BMI 拓扑双维护）；②单巨型 ora.game 模块（touch 底层接口仍全仓波及，收益不可观测）；③头单元（import <header>;，cpp26.md 已禁）；④每头一模块（模块数爆炸，BMI 编译调度开销反噬）。基线与实测收益数据见 #49 票评论。
