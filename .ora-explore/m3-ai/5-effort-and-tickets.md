# Issue #46 §5：工作量模型 + M3 切票建议 + 决策票证据矩阵模板（2026-11-10）

口径与证据等级同 §1。工作量换算沿用 #43 方法论：以 M1 实测为标尺（17 票 / 5 有效 agent 日 / 人类等价 5-10 人月点估 7，产出 34.7k 行验证代码），任务分解法 + 产出速率法双估，1 人月=22 有效人日。agent 工作流与本仓历史节奏同构，故票粒度按 M1/T 票惯例给。

---

## 一、M3 工作包分解（证据：§1-§4 笔记）

M3 = 三正交工作包（§1 笔记 §二 的解耦结论）：

- **A. lua 引擎 + 绑定**（三路线工作量不同，绑定层 API 面三路线共享）
- **B. bot 面**（ModularBot + BotModule + 三个 D 编号架构欠账兑现 + 订单通道扩展）
- **C. 验收接线**（golden_gen bot 剧本 / 大堂 slot_bot+UI / Session 玩家链）

## 二、分路线工作量模型（人月，点估+区间）

## 三、M3 切票建议（T 工单序列草案）

前提：决策票先裁引擎路线；bot 面（B/C）不依赖该裁定可先行。建议序列（编号接 M2 的 T28 之后，票粒度按 M1 惯例一票一验收面）：

| 票 | 内容 | 验收面（一句话） |
|---|---|---|
| T29 决策票（HITL，非 T 工单） | 引擎路线三选一（§四 模板）+ lua 面进 M3 深度（§1 笔记 §六·2） | 维护者拍板，产出 ADR 立项结论 |
| T30 bot 框架 | ModularBot+LocalRandom+激活链+订单节流+RunUnsynced 等价断言 | 同种子双跑「空 bot（无模块）」N 帧摘要恒等且 rng_shared 账本零消耗 |
| T31 移动 Activity 化 | Move/AttackMove 订单世界内 resolve（D044 桥移动面并轨第一步） | 现有 move 黄金零回归 + 新订单流逐帧 SyncHash 进全量对拍面 |
| T32 战斗 rng 面 | AutoTarget/TakeCover/Veterancy 消耗序语义化（D036①/D054 常量退役） | ore-lord 真回放黄金零回归（isync-changes 对应列撤销）+ 新增 bot 交战剧本对拍绿 |
| T33 HPF | 层级寻路（D025 兑现） | movepair 远距对（已入库资产）逐格对拍绿 + HPF==A* 交叉断言面扩展 |
| T34 生产类 BotModule | UnitBuilder+Harvester+BuildingRepair+PowerDown+PowerDown 门控 | golden_gen bot 剧本（回放重演口径）：bot 出兵/维修/停电行为经录包 C++ 重演逐帧 SyncHash 全等 |
| T35 建造与部队 | BaseBuilderBotModule+BaseBuilderQueueManager+SquadManager+Squads 状态机 | bot vs bot（normal）回放重演黄金全等 + 关键决策点（建电/造厂/组队进攻）rng 账本逐帧对齐 |
| T36 支持力与扩张 | SupportPowerManager 基建+SupportPowerBotModule+Mcv 两模块+Minelayer+Capture | normal 类型全模块 live 对拍：双侧定种子 LocalRandom 首个 N 帧订单序列恒等 |
| T37 大堂 bot 槽 | slot_bot 命令受理（D082 扩展）+大堂 UI bot 槽+开局玩家链 BotType | 口径②：人类 vs bot 经大堂 bot 槽开局可玩（手动验收+session 序列化黄金） |
| T38 live bot 收口 | 4 类型全量 live 对拍+desync 负样本 | 口径①B：无头 bot vs bot 全新对局（定种子）逐帧 SyncHash 黄金全等 + 篡改检出 |
| T39 lua 引擎（视 T29） | vendored 入库（若①）/解释器（若②③）+沙盒+context 生命周期 | probe.lua 语义对拍样本全绿（§2 笔记 §五：遍历序/数值/错误串/截断） |
| T40 lua 绑定最小通路 | 绑定协议+最小 API 子集+一张带脚本遭遇战图（fort-lonestar 或合成图） | 该图无头开局逐帧 SyncHash 对拍绿（触发 Trigger/Utils.Random 消耗序） |

排序理由：T30-T33 是无上游不确定性欠账兑现（先还债再叠逻辑）；T34-T36 按「订单类型复用度」递进；T38 收口在 T36 后而非 T37 后（对拍验收不依赖 UI）；T39-T40 可与 T34-T38 并行（不同工作包）。

## 五、ADR 立项建议（User Story 12）

引擎选型满足 ADR 三条件：**难逆转**（绑定层 API 形态随引擎扩散，换引擎=绑定层重写）；**无上下文则费解**（「上游明明是原生 Lua 5.1.5 为何讨论 MoonSharp」——本票 §一 的认知修正若无 ADR 沉淀，未来读者会重蹈）；**真实权衡**（三路线成本差 1.5-6 人月、风险性质互异）。**建议决策票收口时立项 ADR-0005（lua 引擎选型）**，正文引用 §1/§2 笔记锚。bot 面（ModularBot 移植）不满足难逆转条件（常规 trait 移植），不立项。
